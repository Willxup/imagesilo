# ImageSilo UI 重构：设计推敲与实施方案

本文保留 UI 重构时的设计与验收记录；原 Playwright 测试已移除，当前验证方式见[浏览器验收清单](../browser-acceptance.md)。

状态：第二轮设计稿，作为实施依据。本文与交互原型优先于 `docs/ui-redesign.md` 的第一版方向稿。默认采用 A 工作室结构和 C 暗房的深色配色，用户后续反馈可继续调整；这不是用户已确认的偏好。

## 1. 产品体验要变成什么

ImageSilo 是个人维护的图片空间。最常见的行为是把图片放进来、找到某张图片、拿走可用的链接。界面应该围绕这三个行为建立秩序，再为迁移、权限和维护提供完整入口。

设计关键词是「安静的画布、清楚的操作、连续的反馈」。图片可以复杂，包围它的界面应稳定。品牌来自既有 Logo 的蓝、青、绿叠层，不另造品牌，也不把三色渐变铺满所有按钮。

### 当前界面的实测问题

已打开本地原版登录与上传页面观察：

- 大幅几何背景同时出现在登录和工作区。它持续占据注意力，和用户图片争夺视觉焦点。
- 上传页由标题、运行参数、卡片标题、巨大拖放框、操作栏、第二个巨大空状态组成，重复传达「选择文件」。
- 页面之间沿用相近的后台卡片样式，但图片详情、图库、配置表单本应有不同的信息层级。
- 全局搜索和图库搜索的视觉权重接近。侧栏悬停扩展容易让工作区位移。
- 代码已有进入动画，但不能因此认定整体体验连贯。还需考虑退出、打断、返回位置、加载与错误等完整过程。

## 2. 比较过的三种构图

交互原型 `docs/design/index.html` 可直接切换三种构图；使用六张实图，而非空卡片评估。

| 方向 | 主要收益 | 代价 | 结论 |
| --- | --- | --- | --- |
| A 工作室：紧凑侧栏 + 白色工作画布 | 七个功能入口可见，图库与表单都容易组织，频繁切换稳定 | 侧栏占用约 224px | 作为整体结构基础 |
| B 展廊：顶部导航 + 全宽图片 | 影像展示开阔，适合纯图库 | 管理入口变密；缩窄后需要隐藏文字或额外菜单 | 保留开阔、少边框的图片呈现方式，不作为默认导航 |
| C 暗房：深炭色背景 + 清晰影像 | 图片色彩突出，适合夜间使用 | 表单边界和次要文字容易丢失 | 作为 A 的深色主题，单独配色，不做简单反色 |

第一轮原型修订已经去掉假空间切换器：当前产品没有多工作区能力，不应该画一个看起来可以切换的入口。也提高了图片文件名和元数据字号，纠正了暗色继承造成的低对比文字。

保留 A 的侧栏，不等于保留旧页面：上传、详情、管理页的内容结构都会重做。图库卡片取消外层厚重容器，让图片边界成为主体。

## 3. 信息架构与导航

桌面侧栏宽 224px；紧凑桌面可以手动收为 72px，禁止悬停自动展开。移动端使用一套抽屉导航，不额外引入重复底栏。

分组：

- 图片：上传图片、图片库、迁移文件、路径映射。
- 管理：API 令牌、设置、系统状态。

路由不变，`/admin` 仍进入上传。中文显示名称可以简化，但英语、本地存储键、API 和直链均兼容。

顶部：当前位置、搜索入口（Cmd/Ctrl+K）、主题、语言、账号。搜索入口在移动端可简化为有无障碍名称的图标。账号仍有资料入口与退出。标志仍链接仓库，版权、License、版本信息仍可访问。

不引入相册、标签、收藏、多空间、趋势图或多用户等原产品没有的承诺。

## 4. 三条核心使用路径

### 上传 → 得到链接

1. 初始：左侧为有 Logo 叠层意象的拖放区，右侧为可见性和上传按钮。支持格式明确显示；批次数量作为辅助限制。空队列只保留一行说明。
2. 选择：队列在原位置展开，每项显示真实本地缩略图、文件名、大小和等待状态。不能用图片图标代替全部预览。预览 URL 需在清空/卸载时回收。
3. 上传：选项与提交状态明确，原有并发、取消、重试语义保留。进度条在同一 DOM 节点上平滑更新，不能每次更新都重新挂载。
4. 完成：原行就地变为完成状态，复制链接接替进度区域；尺寸不突然跳变。多项成功时显示一次「复制成功链接」，失败项不混入链接集合。
5. 出错：不支持格式、超出上限、网络失败分别有具体提示。保留已成功条目，可针对失败项重试。不会用全屏失败状态抹掉队列。

移动端：拖放/选择区域约 300px 高，可见性和上传按钮在其后，队列紧随；不要把巨幅装饰放在实际操作前面。上传和复制主要控件至少 44px 高。

### 找图 → 筛选 → 批量处理

1. 初始展示图片网格，标题区只保留图库名称、说明和上传入口。
2. 常用可见性可用「全部 / 公开 / 私密」轻量标签切换；它们与同一个 URL 筛选值绑定，不维护第二套冲突状态。
3. 文件名/路径/ID 搜索、格式、来源在筛选面板；日期、尺寸、文件大小在高级部分。筛选收起后保留条件数量/已应用状态和清除入口。
4. 网格图像比例固定以稳定布局；详情完整显示原始比例。列表模式展示更丰富元数据。记住视图偏好和原有筛选偏好。
5. 卡片始终可用键盘进入；选择框独立，复制与操作菜单独立，不触发卡片导航。触屏下这些操作不依赖悬停。
6. 选中后显示底部批量栏：数量、复制/格式、可见性、更多（删除）、清空。紧凑布局中操作可以收纳到菜单，但不能被裁切。
7. 删除保持快照与二次确认，等待中防止重复提交。部分失败需保留结果反馈，不能只显示一个成功动画。

计数规则：没有来自当前查询的可靠总数时，显示「已加载 N 张」，或不显示计数；不把分页第一批数量写成图库总量。原型中的 6 只是明确标示的样例。

移动端：375px 默认两列预览，文件名可截断但详情可读全名；元数据不少于 11–12px。列表模式为另一种可读密度。批量栏距底部安全区留空，上方菜单基于视口定位，内容区预留栏高。

### 打开图片 → 复制/编辑 → 回到原位置

1. 图库缩略图到详情大图使用一次共享图像过渡，让用户感到是同一张图片展开。前后景只有短交叉淡入，不再叠加第二个整页飞入。
2. 桌面左侧大图、右侧约 300px 检查面板；首要操作是复制链接，格式菜单与它相邻。公开/私密为清楚的状态操作。
3. 查看原图、转换 WebP、删除保留。危险动作与常用复制动作分隔，转换仍解释覆盖文件但保留 ID/直链的含义。
4. 上传时间、来源、文件大小、尺寸常显；哈希和处理摘要放在次级信息块，仍能完整查看/复制。
5. 历史路径在同一检查区域或其下方，保留添加和已有列表。不能因版面简洁而省略这项能力。
6. 返回恢复筛选、列表模式和滚动位置。导航立即响应，不依赖 220ms 定时器结束才执行。直接访问详情路由仍能返回图库。

移动端顺序：返回、图片、名称/状态、主要操作、元数据、历史路径、危险操作。主要复制按钮在元数据长列表之前，不能藏在一屏以下。

## 5. 其他页面的具体组织

| 页面 | 新组织 | 必须保留 |
| --- | --- | --- |
| 迁移文件 | 与图库同构；顶部轻量状态条展示只读/可删除；路径比日期更醒目 | 扫描中、刷新、跳过文件提示、路径/格式筛选、网格/列表、分页、原路径打开/全部复制格式、允许时单个/批量确认删除 |
| 路径映射 | 顶部「创建 / 解析」两个清楚的工作区，下方已有映射列表 | 路径、文件上传、来源标记、创建结果、解析结果、分页、复制/打开、确认删除、错误 |
| API 令牌 | 创建表单与已有令牌分区；权限为清楚的勾选行；一次性密钥为显著结果面板 | 四种 scope、到期日期/时/分、名称验证、明文复制、有效/过期/吊销状态、到期展示、吊销确认 |
| 设置 | 局部分区导航：个人资料、上传与处理、账号安全；每项独立保存 | 名称/邮箱、默认可见性、压缩开关及三项质量参数、转换开关/质量/无损、当前/新密码、字段校验、保存反馈 |
| 系统 | 第一层图片/存储指标；第二层运行资源；第三层索引健康与维护时间线 | 数据库/图片/别名计数、迁移占用、RSS/heap/heapSys/goroutines、索引一致性与缺失图片、立即巡检、确认重建、全部维护摘要 |
| 登录 | 留白的品牌构图 + 聚焦表单；大幅叠层图案只在独立品牌区域 | 邮箱/密码、错误、提交中、主题/语言、原跳转地址、已登录跳转、页脚 |
| 初始化 | 同一品牌语言，窄阅读宽度的分组表单 | Bootstrap token、资料/邮箱、两次密码、默认可见性、压缩/转换、错误、完成后进入上传 |

本次不更改后端：已有接口已满足这些行为。服务器部署选项和迁移删除开关不搬进 UI。若统计计数或上传策略只能从其他接口获取，优先避免增加只为装饰的请求。

## 6. 视觉系统

| 层次 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| 外层画布 | `#f2f4f4` | `#101719` | 安静的边界 |
| 主表面 | `#ffffff` | `#19252c` | 内容与表单 |
| 次级表面 | `#f7f9f9` | `#213039` | 上传选项、微弱分组 |
| 正文 | `#17262d` | `#e6edef` | 标题、正文 |
| 次要文字 | `#5e6e75` | `#a1b0b7` | 说明、元数据 |
| 操作蓝 | `#2466e8` | 浅蓝底配深色文字 | 主要动作、焦点 |

- 正式使用原始 Logo 和既有深色资源；叠层插画是辅助图形，不替换 Logo。
- 32px 页面标题，24px 图片详情标题，16px 小节标题，14px 操作/正文，12px 元数据。中文用系统字体，不依赖外链字体。
- 卡片内容保持疏密差异：图片区不加一层无意义的白色外框；表单靠区块标题、间距和细分隔线建立结构。
- 色彩占比由用户图片决定。品牌三色只在 Logo、上传插画、状态和少量强调上出现。
- 图标采用现有 Lucide，线宽与尺寸统一。图标按钮必须有标签，色彩不能单独传达权限/错误/选中。
- 控件高 40px，手机主要控件 44px；圆角：控件 10px、图片 12–14px、主画布 24px。视觉小的选择框扩大命中区域。

## 7. 动效分镜与实现约束

| 触发 | 画面变化 | 进入 / 退出 | 关键约束 |
| --- | --- | --- | --- |
| 一级导航 | 活动项立即更新；新内容一次轻淡入 | 180ms | 不再叠加标题/每张图片的入场；历史返回不重演淡入；指向/聚焦导航时预加载对应代码 |
| 图库 → 详情 → 返回 | 只有当前图片从缩略图过渡到大图，再收回 | 图像 300ms，背景 140ms | 不为全库图片建立过渡快照；元数据加载前后图片区域尺寸不变；返回先恢复滚动再绘制 |
| 卡片悬停 | 图片 scale 1.025，操作清晰显现 | 240ms / 180ms | 只有精确指针悬停适用；焦点/触屏同样可操作 |
| 选中图片 | 边框/勾选即时变化；批量栏从下方 12px 出现 | 260ms / 160ms | 不改变网格尺寸；数量只更新文字，不重演整个动画 |
| 拖入文件 | 叠层轻微散开，边界高亮 | 300ms / 220ms | 鼠标移出收回；选择文件触发也有明确状态 |
| 上传进度 → 完成 | 同一条进度更新；结束替换为完成与链接 | 180–240ms | 不每帧重新挂载、不虚构 100%；取消/失败立即可见 |
| 筛选/高级选项 | 容器短展开，内容淡入 | 220ms / 160ms | 关闭项 inert，不能 Tab 到不可见输入 |
| 菜单/弹窗/抽屉 | 独立前景轻位移与淡入，背景短淡入 | 菜单 140ms、弹窗 180ms、抽屉 260ms | 菜单/弹窗用可逆 CSS transition；弹窗从首次绘制前接受键盘输入；滚动条留位避免背景横跳 |
| 复制完成 | 原按钮短变成勾选，轻量 toast | 140ms | 不移动布局、不弹出遮挡操作的确认对话框 |

统一 easing：`cubic-bezier(.22,1,.36,1)`；退出可略快。禁用持续漂浮、无限光带、背景粒子、复杂 3D 和整页缩放。正常浏览时页面静止，只有操作引发运动。

实现优先级：已有组件 + CSS 状态过渡；原生 View Transition 可用时用于共享图片，并提供普通导航回退。进入和退出状态需配套，不能仅靠统一 `.page-transition` 动画。减少动态效果时取消位移、缩放、错峰和共享图像飞行，只保留即时状态/极短淡入。

原型验证中发现：反复重建上传行会使进度条没有连续插值，已改为更新现有节点。这条约束必须同步到正式实现。

用户反馈后的收敛：侧栏最底部只保留收起/展开按钮，移除三色装饰条。折叠时标签保持同一 DOM 节点、单行逐渐收拢，避免换行挤压导航；禁止浏览器在侧栏变宽/变窄时自动重选滚动锚点。普通页面保持轻淡入，图库移除逐张错峰等待。弹窗取消背景模糊和内容缩放，保留短位移与遮罩，使文字保持清晰。减少动态效果时，覆盖 CSS 的同时也取消菜单/弹窗的卸载等待。

## 8. 必须画清楚的状态

- 图库：首次空库（有上传入口）、筛选无结果（清除筛选）、加载中（固定比例占位）、失败（重试）、满页/加载更多、长文件名、私密、选中、批量处理中。
- 上传：初始、拖入、排队、进行中、已取消、部分失败、单项完成、整批完成、浏览器不支持的文件。
- 管理表单：初始加载、保存中、成功、字段错误、接口错误；失败保留草稿。
- 菜单：首尾方向键/Tab、Escape、点击外部、窄屏靠边；关闭后还原触发器焦点。
- 图片详情：直接打开、从筛选结果进入、网络慢、加载失败、不存在、转换中、确认删除。

## 9. 开发拆分与验收方式

先冻结桌面/移动图库、上传、详情、登录以及主题的视觉，再交给 GPT-6 Sol（xhigh）。由主代理持续审查，不把原型样例数据带进产品。

1. 基础层：语义 tokens、按钮/输入/菜单/弹窗、Logo/品牌图形、动效和减少动态效果。
2. 导航与登录：新的稳定 shell、全局搜索、手机抽屉、登录/初始化、主题与语言。
3. 核心图片工作流：上传 → 图库 → 详情，先保证连续性，再接完整筛选、复制格式、批量动作与错误状态。
4. 管理页面：迁移、路径映射、API 令牌、设置、系统，以功能映射表逐项核对。
5. 真实数据验收：所有页面在浅/深色及中/英文可用；375、768、1024、1440px 验证。主要页面以实际图片检查，不以全空页面代替。
6. 键盘/减少动态效果/菜单边缘/慢网络检查；运行 `make check`，并按浏览器验收清单检查相关用户流程。
7. 主代理独立浏览与代码审查后才接受。实现不授权 commit、push、PR、发布或部署。

样式应拆分为 tokens/base、shell、controls、pages、motion 等清楚的层次；删除替换掉的 TailAdmin 样式，禁止在 3106 行旧 CSS 后堆叠另一套覆盖系统。不能为追求一次性改全而把功能性组件推翻重写。

## 10. 当前设计证据与待办

已完成：原版登录/上传观察，Logo 检查，三种构图的实图比较；工作室/暗房配色检查；图库、详情和上传队列的交互原型；375px 图库/详情无横向溢出检查；设置分区；登录/初始化品牌构图；迁移、路径映射、令牌、系统页面具体布局。

第二轮修订：

- 移动端详情将复制/格式/查看原图放在长元数据之前。正式 DOM 顺序也要与视觉顺序相符，不能只用 CSS order 造成键盘顺序错乱。
- 详情复制按钮与格式菜单组合成一行；批量栏保留独立的格式、可见性、更多、清空入口，手机也不能隐藏删除入口。
